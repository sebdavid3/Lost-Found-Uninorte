Lost & Found Uninorte

Sistema de gestión de objetos perdidos · Universidad del Norte

NestJS 11 React 19 Prisma 5.22 TypeScript 5.7 PostgreSQL 15 RabbitMQ 3 Docker Compose TailwindCSS 4

El problema

  • Estudiantes y personal pierden objetos frecuentemente en campus universitarios.
  • No existe un sistema centralizado de registro y búsqueda de objetos perdidos.
  • La verificación de propiedad se hace manualmente, sin trazabilidad ni auditoría.
  • No hay registro inmutable de quién manipuló un reclamo y cuándo.
  • Los administradores necesitan filtros, estadísticas y control de acceso por rol.
Impacto esperado
  • Reducción de tiempos de búsqueda
  • Trazabilidad completa (SHA-256)
  • Verificación automatizada de evidencias
  • Escalabilidad por microservicios
  • Auditoría forense de reclamos

Chain of Responsibility

EvidenciaHandler

Verificación de propiedad
  • BaseHandler: define setNext() y handle().
  • PhotoHandler: valida fotos del objeto.
  • ReceiptHandler: valida facturas o recibos.
  • DescriptionHandler: valida descripción detallada.
class EvidenceHandlerChain {
  constructor() {
    this.chain = new PhotoHandler()
      .setNext(new ReceiptHandler())
      .setNext(new DescriptionHandler());
  }
  verify(claimId, evidence) {
    return this.chain.handle(claimId, evidence);
  }
}

Principio SOLID: Open/Closed — nuevos handlers sin modificar la cadena existente.

Visitor

AuditEventVisitor

Generación de eventos de auditoría
  • ClaimVisitor: interface con visitClaim().
  • AuditEventVisitor: implementa visitClaim.
  • Desacopla la lógica de auditoría del dominio Claim.
  • Permite añadir nuevos tipos de visita sin tocar Claim.
class AuditEventVisitor implements ClaimVisitor {
  visitClaim(claim: Claim): AuditEvent {
    return {
      claimId: claim.id,
      userId: claim.userId,
      objectId: claim.objectId,
      timestamp: new Date(),
      type: 'AUDIT_EVENT_CREATED'
    };
  }
}

Principio SOLID: Single Responsibility — Claim no conoce auditoría.

Abstract Factory

ClaimFactory

Creación de claims según rol
  • ClaimFactory: interface abstracta.
  • StudentClaimFactory: claims con evidencia básica.
  • AdminClaimFactory: claims con verificación prioritaria.
  • El servicio inyecta la factory según el rol del usuario.
@Injectable()
class ClaimService {
  constructor(
    @Inject('CLAIM_FACTORY')
    private factory: ClaimFactory
  ) {}
  createClaim(dto) {
    return this.factory.create(dto);
  }
}

Principio SOLID: Dependency Inversion — depende de abstracción, no de clases concretas.

Proxy + ACL

AuthGuardProxy

Control de acceso por rol
  • AuthGuard: valida JWT antes de cada request.
  • RolesGuard: verifica roles (STUDENT, ADMIN).
  • JWT Strategy: extrae y valida el token.
  • Decoradores @Roles() + @UseGuards() en endpoints.
@Controller('claims')
@UseGuards(JwtAuthGuard, RolesGuard)
export class ClaimController {
  @Post()
  @Roles(Role.STUDENT)
  create(@Body() dto: CreateClaimDto) {
    return this.service.create(dto);
  }
  @Get('admin/stats')
  @Roles(Role.ADMIN)
  getStats() {
    return this.service.getStats();
  }
}

Principio SOLID: Single Responsibility — autenticación separada de la lógica de negocio.

Transactional Outbox

Outbox pattern

Garantía de entrega de eventos
  • Tabla outbox en la misma transacción del claim.
  • Estados: PENDING, SENT, FAILED.
  • FOR UPDATE SKIP LOCKED para reservar lotes.
  • Procesador periódico reintenta eventos fallidos.
async reserveBatch(size: number) {
  return this.prisma.$queryRaw`
    SELECT * FROM outbox
    WHERE status = 'PENDING'
    ORDER BY created_at ASC
    LIMIT ${size}
    FOR UPDATE SKIP LOCKED
  `;
}

Patrón de integridad: at-least-once delivery con idempotencia.

Service Discovery

Consul + Health Checks

Descubrimiento dinámico
  • Registro en Consul al arrancar con @nestjs/consul.
  • Health check HTTP /health cada 10s.
  • Balanceo aleatorio entre instancias registradas.
  • Deregister automático tras 30s de fallos.
@Injectable()
class ConsulService {
  async register(service: string, port: number) {
    await this.consul.agent.service.register({
      name: service,
      port,
      check: {
        http: `http://host.docker.internal:$${port}/health`,
        interval: '10s',
        timeout: '5s',
        deregistercriticalserviceafter: '30s'
      }
    });
  }
}

Resiliencia: failover automático sin intervención manual.

Audit Trail (SHA-256)

Cadena de hash inmutable

Trazabilidad forense
  • Cada evento genera hash = SHA256(prevHash + data).
  • Tabla AuditLog con previousHash encadenado.
  • Endpoint GET /verify-integrity recalcula y compara.
  • Detección de alteraciones: hash mismatch = alerta.
private generateHash(log: AuditLogInput): string {
  const data = log.previousHash +
    log.claimId +
    log.action +
    log.timestamp.toISOString();
  return createHash('sha256').update(data).digest('hex');
}

Integridad criptográfica: cualquier modificación rompe la cadena.
